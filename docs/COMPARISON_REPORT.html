方法、稽核與限制

  • 架構差異：baseline＝Analyzer → Writer（可平行分割）→ Executor → Reviewer（1+4）；lite＝Author（分析＋場景推導＋撰寫＋建置修正）→ Reviewer（獨立審查＋驗證執行＋coverage），全循序、單一類別上限、技能白名單 14＋1。
  • 品質優勢來源：lite 的兩項 coverage 優勢皆源自其場景推導紀律（public 建構子強制列管、guard／分支展開規則），各 target 三輪與跨 framework 一致支持系統性效果；已通過「示例去名化後重驗」確認非示例記憶（詳私有 lab repo 稽核章節）。
  • 可移植性：於隔離環境（獨立專案、工作流程從未見過的自創類別、僅複製部署單位、無 lab 文件）完整跑通：25/25 全綠、100%/100%、可選配件缺失時優雅降級，工作流程不依賴 lab 環境。
  • 限制：wallclock 僅 OrderValidator 一個 target 兩側可比（其餘 baseline 為平行執行）；lite 側 token run-to-run 離散約 ±20%，大於 baseline（單一 Author 場景推導規模波動），協定以中位數比較故不影響結論，列為後續優化線索；範圍限 xUnit 單元測試工作流程。
  • 資料效力：45 次 claude -p 呼叫、42 個有效樣本格（Stage 1 net10 各 n=3＋Stage 2 net8/9 各 n=1＋2 次確認輪），3 次用量上限中止皆依協定作廢重跑、零數據污染；每 run 環境還原有逐輪驗證紀錄。
